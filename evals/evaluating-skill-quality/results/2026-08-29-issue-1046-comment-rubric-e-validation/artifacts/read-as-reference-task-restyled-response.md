Because the window is a raw character count, it can not tell "these two substrings are semantically bound in the same statement" apart from "the response was simply terse enough that two unrelated substrings happened to fall close together." Concretely, if a compact response lists several distinct items back-to-back (e.g., one repair's description followed immediately by a different repair's classification label, or a correct label sitting near an adjacent-but-wrong entry), the correct substring and the wrong substring could both land within the character window purely due to terseness, causing a false positive on the wrong pairing. The blank-line check adds the actual structural signal, it requires the two occurrences to sit in the same paragraph or list item, not merely within N characters of each other, which is what actually distinguishes true binding from accidental proximity, since a verbose correct pairing and a terse unrelated pairing can straddle any fixed character window either way.
