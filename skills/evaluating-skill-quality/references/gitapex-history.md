## Issue 444: Copilot, Kiro, and Windsurf rows; Amazon Q Developer non-addition

https://github.com/tvna/gitapex/issues/444: GitHub Copilot and Kiro rows were added to the baseline on 2026-07-27, each grounded in official documentation fetched directly that session (github/docs source files for Copilot; kiro.dev for Kiro). A Windsurf row was added in a same-day follow-up once the owner allow-listed docs.devin.ai (Cognition, Devin's maker, now hosts Windsurf's docs at a separate page on that domain): it documents only name/description in SKILL.md frontmatter, with no allowed-tools claim, so its row is kept independent from the existing Devin row rather than conflated with it. Amazon Q Developer proper was investigated last and resolved as a non-addition, closing https://github.com/tvna/gitapex/issues/444. The aws/amazon-q-developer-cli README (fetched directly) states the project 'is no longer being actively maintained' and 'is now available as Kiro CLI, a closed-source product'; the official AWS DevOps blog end-of-support announcement (fetched directly once the owner allow-listed aws.amazon.com), confirms Q Developer IDE plugins and paid subscriptions reach end of support on 2027-04-30 with a 12-month transition window to Kiro, stating 'Kiro also includes everything developers rely on in Q Developer today' -- so its Skills-relevant successor is the already-cataloged Kiro row. The same announcement notes Amazon Q in the AWS Management Console and other first-party AWS experiences is unaffected by this sunset, so this finding is scoped to the Q Developer coding-agent product specifically, not all of Amazon Q. A separate 'Agent Toolkit for AWS' project was also checked and confirmed (via its own README) to be AWS-specific skill/plugin content consumed by other runtimes (Claude Code, Codex, Cursor, Kiro), not a runtime that parses SKILL.md itself -- the same category as the earlier MiniMax finding.

https://github.com/tvna/gitapex/issues/443: Kimi CLI and Cursor rows were added to the baseline on 2026-07-27, each grounded in that vendor's official documentation fetched directly during the session (cursor.com's skills-documentation page was initially blocked by the session's egress policy, then fetched successfully once the owner allow-listed the domain). No primary source documents a distinct MiniMax-owned runtime (the 'MaxClaw' name did not appear in either fetched page).

## Issue 445: Axis C scope note and reverted cross-reference draft

https://github.com/tvna/gitapex/issues/445: this repository's own new `docs/agent-product-scope.md` formally distinguishes this evidence baseline (Axis C: skill-quality-review evidence, currently eleven runtimes) from GitApex's plugin-distribution target (Axis A: Claude Code, per this repository's `docs/repository-layout.md`) and the https://github.com/tvna/gitapex/issues/307 enforcement-adapter target set (Axis B: six runtimes), and names this file as Axis C's owning evidence. An earlier draft of this change, within this repository, added a body cross-reference sentence directly to references/runtime-compatibility.md pointing at `docs/agent-product-scope.md`; that was reverted after review because a Portable skill's own references/*.md content should not carry a relative link that escapes the skill's own directory -- it would 404 once this skill is vendored into a different repository, and check_skill_shape.py's repo-path-citation checks do not currently catch a Markdown-link-shaped instance of this (they exempt Markdown links entirely, by design, for a different concern). This provenance note carries that cross-reference instead, since sidecar notes are maintainer bookkeeping for this specific repository, not portability-scanned skill content -- the same reasoning behind this file's own first reference bullet above. No runtime was added, removed, or reclassified in this baseline as part of any of this.
