# Issue #991: Isolate the Real-Checkout Session-Start Hook Test

> **For agentic workers:** REQUIRED SUB-SKILL: This plan is dispatched by
> `executing-a-branch-plan` (one `Workflow` run per wave). Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** `tests/test_gitapex_session_start_hook_shell.py::test_installs_the_prek_hook_for_a_real_checkout`
writes into this repository's own real `.git/hooks/pre-commit` (verified:
`prek install` rewrites the file's mtime unconditionally, even when its
content is byte-identical), a write no pytest-xdist worker owns and that
survives the test run on a developer's or CI runner's own checkout. Stop
that write without losing the test's real-checkout coverage, then add a
deterministic gate so the same hazard shape cannot silently return.

**Architecture:** Point the one test that currently targets `REPO_ROOT`
at a throwaway local git clone under `tmp_path` instead -- a `git clone -q
--depth 1 --no-tags file://<REPO_ROOT> <tmp_path>/checkout` carries over
the current commit's real `apm.yml`/`.pre-commit-config.yaml`/`uv.lock`
(all tracked files), so the prek-install step still runs against a
genuine git repository with genuine config, not a synthetic `tmp_path`
fake. Separately, add `.github/scripts/gitapex_gate_real_checkout_git_write.py`,
a new `local`-plane gate (`behind-base`'s minimal-footprint precedent: no
dedicated CI workflow, discovered by `gitapex_gate_local_preflight.py`
and exercised in CI only via its own pytest test file inside `test.yml`'s
existing pytest step) that flags any `REPO_ROOT`-rooted, `.git`-segment
path expression in a pytest-discovered test file, with an inline
`# real-checkout-git-write: WAIVED: <reason>` escape hatch mirroring
`gitapex_gate_exception_handler_gaps.py`'s own waiver convention.

**Tech Stack:** Python 3, `pytest`/`pytest-xdist`, `git`, `prek`, `uv run`,
this repository's own gate-registry convention (`.gitapex/ssot.json`).

```python
def test_installs_the_prek_hook_for_a_real_checkout(tmp_path: Path) -> None:
    # Issue #749: this ephemeral-web session-start path is the third
    # place (alongside CONTRIBUTING.md's manual step and flake.nix's
    # devShell shellHook) prek's hook install must reach -- exercised
    # here against a real checkout (a real .git/ and, by the time this
    # test runs, a real .pre-commit-config.yaml), not a fake project dir.
    #
    # Issue #991: the real checkout in question is a throwaway local
    # clone of REPO_ROOT, not REPO_ROOT itself. REPO_ROOT's own
    # .git/hooks/pre-commit is not owned by any single pytest-xdist
    # worker, and `prek install` rewrites it unconditionally -- verified
    # directly: its mtime changes even when its content stays
    # byte-identical. A `--depth 1` local clone still carries this
    # commit's real apm.yml and .pre-commit-config.yaml (both tracked
    # files), so the prek-install step below still runs against a
    # genuine git repository with genuine config -- the exact distinction
    # this test exists to draw against a `tmp_path` fake, unaffected by
    # which git repository supplies that genuine config.
    checkout = tmp_path / "checkout"
    subprocess.run(
        ["git", "clone", "-q", "--depth", "1", "--no-tags", f"file://{REPO_ROOT}", str(checkout)],
        check=True,
    )
    result = _run({"CLAUDE_CODE_REMOTE": "true", "CLAUDE_PROJECT_DIR": str(checkout)})
    assert result.returncode == 0
    pre_commit_hook = checkout / ".git" / "hooks" / "pre-commit"
    assert pre_commit_hook.exists()
    assert "prek" in pre_commit_hook.read_text(encoding="utf-8")
```
