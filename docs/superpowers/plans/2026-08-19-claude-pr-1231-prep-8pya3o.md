## Task 1 -- Schema shape: `.gitapex/ssot.schema.json`

**Cites ACM row:** "Add `fail_mode`, `target`, and `bypass_review_status` to
`.gitapex/ssot.schema.json`."

**Quoted Planned ops (verbatim from this session's ACM):** "Edit
`.gitapex/ssot.schema.json`; bump `meta.schema_version` 1.1.0->1.2.0 (minor:
additive, backward-compatible)."

**Files:** `.gitapex/ssot.schema.json`.

**Steps:**
1. Add `fail_mode` (object, `additionalProperties: false`, `required:
   ["on_error", "rationale"]`, `on_error` enum `fail-open`/`fail-closed`/
   `mixed`, `rationale` string `minLength: 1`), `target` (array of objects,
   each `additionalProperties: false`, `required: ["kind", "ref"]`, `kind`
   enum `mcp-tool`/`bash-pattern`/`file-glob`/`workflow-event`/
   `github-native`/`cross-registry-consistency`, `ref` string `minLength:
   1`), and `bypass_review_status` (enum `not-yet-reviewed`/
   `reviewed-none-found`/`reviewed-found-listed-below`) to
   `$defs.gate.properties`, exactly as drafted in issue #1231's own body
   (description text included, verbatim).
2. Do not add any of the three to `gate.required[]` (issue's own explicit
   constraint).
3. `meta.schema_version`'s value is a data change (task-3, in this revised
   order), not a schema-file change -- this step only confirms the schema's
   own `schema_version` property definition needs no shape change (it is
   already a free-form semver string pattern).

**Proof method:** direct read confirms all three properties exist with the
stated shape; `jsonschema.Draft202012Validator` (invoked via
`gitapex_scan_ssot_schema.py`) still reports zero violations against the
*pre-backfill* `.gitapex/ssot.json` (0/62 gates carrying any of the three
fields at this point in the sequence -- task-3 has not run yet).

## Task 2 -- Keep drift-checking alive: pydantic mirror + regression/defeat test

**Cites ACM row:** the third row this plan's own independent re-verification
added (not in the issue's own table) -- "Keep `ssot-schema-drift`'s
reference-drift checking alive across the backfilled registry." Sequenced
before the data backfill in this revision (see "Revision" above) so the
parser is always in place before any real gate carries the new fields.

**Quoted Planned ops (verbatim from this session's ACM):** "Add
`GateFailMode`/`GateTargetEntry` models + 3 optional `Gate` fields mirroring
the schema" and "New regression test: a gate carrying `bypass_review_status`
(and `fail_mode`/`target`) still parses into a typed `Gate`, and a
deliberately-broken script path on such a gate is still caught by
`find_script_drift` (the defeat test for this exact blind spot)."

**Files:** `.github/scripts/gitapex_scan_ssot_schema.py`,
`tests/test_gitapex_scan_ssot_schema.py`.

**Design, fixed at decomposition time:**
- `GateFailMode(BaseModel)` (`extra="forbid"`): `on_error: Literal["fail-open",
  "fail-closed", "mixed"]`, `rationale: str`.
- `GateTargetEntry(BaseModel)` (`extra="forbid"`): `kind: Literal["mcp-tool",
  "bash-pattern", "file-glob", "workflow-event", "github-native",
  "cross-registry-consistency"]`, `ref: str`.
- `Gate` gains three new optional fields, appended after `supersedes`:
  `fail_mode: GateFailMode | None = None`, `target: list[GateTargetEntry] |
  None = None`, `bypass_review_status: Literal["not-yet-reviewed",
  "reviewed-none-found", "reviewed-found-listed-below"] | None = None`.
  Bare `str`/no extra length constraint on nested string fields, matching
  this file's own existing convention (jsonschema is the strict validator;
  pydantic is the secondary typed-access layer, per `Gate`'s own docstring).

**Steps:**
1. Red: add a regression test asserting a gate dict carrying
   `bypass_review_status` (plus `fail_mode`/`target`) parses via
   `drift._parse_registry` into a non-`None` `SsotRegistry` with those
   fields typed correctly -- confirm it fails against the pre-change model
   (extra field forbidden) for the right reason before touching the model.
2. Red (defeat test, per step 8's own gate -- constructed here at task time
   since it exercises this same new code path directly): a second test
   using the same fixture, but with a deliberately-broken `script` path on
   that gate, asserting `find_script_drift` (via `find_drift`) still reports
   the `script-drift` finding -- i.e. the reference-drift suite does not go
   blind for a gate carrying the new fields. Confirm this also fails
   pre-change (empty findings, since `_parse_registry` returns `None` and
   `find_script_drift` short-circuits).
3. Green: add the two pydantic models and the three `Gate` fields above.
4. Run this file's own full existing test suite alongside the two new
   tests. The real-repo test (`test_repository_ssot_is_schema_valid_and_drift_free`)
   is not yet meaningful against the backfilled registry at this point --
   task-3 has not run yet -- so it is re-checked as task-3's own proof
   method instead of here.

**Proof method:** `tests/test_gitapex_scan_ssot_schema.py` full pass on the
two new tests (the parse-success regression and the script-drift-still-
caught defeat test) plus the file's own pre-existing suite, using synthetic
fixtures -- no dependency on the real registry's own data state, which
task-3 has not written yet.
