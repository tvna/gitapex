## Task 1 -- `gitapex_run_ablation.py`: hermetic-by-default + shared-primitive extensions

**Cites ACM rows:** row 5 ("Executor tool surface... hermetic-by-default");
row 2/6 support (the `model`/`graders` extensions task-2 depends on).

**Quoted Planned ops (verbatim from this session's approved ACM):**
"モデルCLI起動コマンド構築ロジックに明示的な権限指定を追加し、
`gitapex_run_ablation.py`のdocstring中「Undecided」記述を更新" (row 5,
Planned ops column) -- "Add explicit permission restriction to the model-CLI
command-construction logic, and update the 'Undecided' note in
`gitapex_run_ablation.py`'s docstring." Extended per this session's own
follow-up primary-source verification (`claude --help`, fetched live in this
session): `--bare` alone still leaves Bash and file read/edit tools
available -- confirmed the true "no tools at all" mechanism is `--tools ""`
(the CLI's own `--help` text: "Use \"\" to disable all tools"), not
`--permission-mode`/`--allowedTools` as the issue's own docstring had
guessed at.

**Files:** `evals/scripts/gitapex_run_ablation.py`,
`tests/test_gitapex_run_ablation.py`.

**Steps:**
1. Change `_FIXED_FLAGS` from `["--bare"]` to `["--bare", "--tools", ""]` --
   verified live against this environment's own installed `claude --help`
   that `--tools <tools...>` "Specify the list of available tools from the
   built-in set. Use \"\" to disable all tools," and that `--disallowedTools
   "*"` is a documented alternative ("removes every tool") not adopted here
   since `--tools ""` is the more directly purpose-built mechanism for
   "restrict availability" per the CLI's own docs
   (`code.claude.com/docs/en/headless.md`: "--allowedTools... To restrict
   which tools are available, use --tools instead").
2. Add `import os` and a module-level `_HERMETIC_ENV_ALLOWLIST = ("PATH",
   "HOME", "ANTHROPIC_API_KEY", "TMPDIR", "TMP", "TEMP")` plus a
   `_hermetic_env() -> dict[str, str]` helper filtering `os.environ` to that
   allowlist. `subprocess_executor` passes `env=_hermetic_env()` to
   `subprocess.run` instead of inheriting the full parent environment --
   defense-in-depth alongside step 1, not a substitute for it, so an ambient
   CI credential (`GITHUB_TOKEN`, `gh`-related vars) set in the parent
   process is never visible to the invoked model CLI even if a future change
   reintroduced tool access by mistake.
3. Add an optional `model: str | None = None` parameter to `build_command`,
   appending `["--model", model]` to argv when given (verified live:
   `claude --help`'s `--model <model>` "Provide an alias for the latest
   model... or a model's full name," e.g. `claude-sonnet-5`) -- `None` omits
   the flag entirely, preserving every existing call site's behavior
   unchanged. `gitapex_run_ablation()`'s own two call sites stay `model=None`
   (unchanged behavior); task-2's suite runner is the first caller to pass a
   real value, reading it from `eval.yaml`'s `config.model`.
4. Extend `load_task_fixture` to also read and return the fixture's
   `graders:` list (per `.gitapex/waza-task.schema.json`'s own optional
   top-level `graders` array), defaulting to `[]` when absent -- returned
   dict shape becomes `{"id", "prompt", "expected", "graders"}`, a strict
   superset of the current three keys so no existing caller destructuring
   specific keys breaks.
5. Update the module docstring's "Undecided, disclosed residual risk"
   paragraph (lines ~50-57) to state the now-decided hermetic-by-default
   policy (citing `--tools ""` and the environment allowlist), and note the
   vendored eval schema's `mcp_mocks` field
   (`.gitapex/waza-eval.schema.json`) stays declarable but unimplemented --
   with zero tools ever granted, there is nothing for it to mock.
6. Red-Green: update `test_build_command_without_skill_md` /
   `test_build_command_with_skill_md` for the new fixed-flags shape; add
   `test_build_command_with_model` / `test_build_command_without_model_omits_flag`;
   add a hermetic-environment regression test asserting a fake ambient
   credential set in the test process's own environment does not reach a
   real subprocess's environment while an allowlisted variable (e.g. `PATH`)
   still does (run against `subprocess_executor` directly, a real
   subprocess, no `claude` binary needed -- same style as this file's
   existing `subprocess_executor` tests); update `test_load_task_fixture_happy_path`'s
   exact-dict assertion for the new `graders` key; add
   `test_load_task_fixture_returns_graders_when_present`. Run this file's
   own full existing test suite alongside the new/updated tests.

**Proof method:** `tests/test_gitapex_run_ablation.py` full pass, including
the new hermetic-environment regression test (which must fail against the
pre-change `subprocess_executor` for the right reason, then pass after step 2
lands).

**Files:** `evals/scripts/gitapex_run_eval_suite.py` (new),
`tests/test_gitapex_run_eval_suite.py` (new).

**Design, fixed at decomposition time so the Red step targets a stable
interface:**
- `load_eval_suite(eval_yaml_path) -> dict` parses `name`/`skill`/`config`
  (`trials_per_task`, `timeout_seconds`, `model` -- the 3 fields this runner
  consumes; other `config:` keys like `parallel`/`workers` are read-and-
  ignored, not required) /`tasks` (glob list). Raises `ValueError` on
  malformed shape, same one-exception-type convention as
  `gitapex_run_ablation.load_task_fixture`.
- `discover_task_fixtures(eval_yaml_path, task_globs) -> list[Path]` resolves
  each glob relative to `eval_yaml_path.parent`, sorted, deduplicated.
  Raises `ValueError` if the combined match set is empty -- fail loudly, no
  silent empty-suite pass (ACM row 2's own residual-risk column).
- `run_text_grader(output, grader_config) -> GraderResult` supports exactly
  `contains`/`not_contains` (case-insensitive per
  `.gitapex/waza-task.schema.json`'s own `textGraderConfig` description,
  implemented by delegating to `gitapex_score_contract.score`'s existing
  `output_icontains`/`output_not_icontains` keys -- not its case-sensitive
  `output_contains`/`output_not_contains`, which is a different contract).
  Raises `ValueError` (fail loud, never silently skip) for any other
  declared config key (`contains_cs`, `not_contains_cs`, `regex_match`,
  `regex_not_match` -- none used by any committed fixture today) or any
  `type` other than `"text"`.
- `run_eval_suite(eval_yaml_path, skill_md, *, executor: Executor,
  model_cli=DEFAULT_MODEL_CLI) -> SuiteResult` -- single-arm (skill always
  injected, matching what `waza run <skill>` did; NOT
  `gitapex_run_ablation()`'s own 2-arm with/without comparison, a different,
  unmodified capability this task does not touch). For each discovered task
  fixture, run it `trials_per_task` times via
  `gitapex_run_ablation.build_command(model_cli, prompt, skill_md,
  model=suite_config["model"])` + the given `executor`, scoring each trial
  via `gitapex_score_contract.score` (`expected.*`) and every declared
  `graders:` entry. A retried dispatch (session usage limits) being
  indistinguishable from a genuine trial is a disclosed, out-of-scope
  residual risk (this session's own resolved ACM row 1 decision) -- stated
  in this module's own docstring, not solved here.
- `SuiteResult`/`to_eval_scores_json` -- aggregate shape:
  `{"model_id", "n_fixtures", "mean_score", "scores": [{"fixture_id",
  "score", "trials": [{"trial_index", "score", "grader_results": [...]}]}]}`
  -- the four required keys plus each `scores[]` entry's `fixture_id`/`score`
  match `skills/scorer-gated-skill-edits/references/eval-scores.schema.json`
  exactly (that schema's own `additionalProperties` is unset, i.e.
  permitted, so the extra `trials` key is schema-compatible, not a
  deviation); not byte-compatible with waza's own undocumented output (this
  session's own resolved ACM row 4 decision).
- `main(argv=None) -> int` CLI: `--eval-yaml`, `--skill-md`,
  `--model-cli` (default `claude`), `-o/--output` (defaults to stdout).
  Same 2/1/0 exit-code convention as `gitapex_run_ablation.py`'s own
  docstring ("Exit code contract").

**Steps:**
1. Red: write `tests/test_gitapex_run_eval_suite.py` covering

2. Green: implement `evals/scripts/gitapex_run_eval_suite.py` per the Design

Red-Green test is re-run (not only the one related to the fix) before the
draft PR converts to ready-for-review.
