# Redesign the provenance-disclosure gate's cue matching into a non-exhaustive invariant

**Goal:** Make `.github/scripts/gitapex_gate_provenance_disclosure.py`
(gate id `provenance-disclosure`) consistent with CLAUDE.md section 4's
"non-exhaustive instances / default-in-scope" invariant, and structurally
fix the self-trigger false-positive class documented in issue #549
(repairs 1 and 8), without regressing detection of the gate's original
positive case (issue #350). Source: https://github.com/tvna/gitapex/issues/978.

**Architecture:** Single file pair, no new files. The gate's two
cue-word regexes (`_LIMITATION_CUE_RE`, `_TOOL_CUE_RE`) are unchanged in
vocabulary but are now explicitly documented as non-exhaustive (matching
`gitapex_scan_provenance.py`'s own established convention). Matching is
redesigned to filter cue-match *positions* rather than rewrite paragraph
text: `_quoted_example_spans` finds every short (<= 6 word,
`_MAX_QUOTED_EXAMPLE_WORDS`), backtick- or straight/curly-double-quote-
delimited span in a paragraph, and `_has_live_match` counts a cue regex
match only when it falls outside every such span. A short quoted/
backtick cue phrase (as the module's own docstring now uses to document
both cue types in one paragraph) is a documented example, not a live
evidence-limitation claim, so documentation of the gate's own vocabulary
can no longer self-trigger the gate -- without letting an entire
offending clause evade detection by quoting the whole sentence, and
without the position-filtering approach's predecessor design (a draft
that textually stripped matched spans, replacing them with a single
space) creating any risk of bridging two previously-unrelated words
across a removed span into a fabricated match. No change to the
`_WAIVER_RE` override or to the workflow wiring.

**Adversarial verification (issue #978, Decision-12-equivalent):** two
independent fresh subagent dispatches ran against this change before it
was marked ready for review -- one adversarial code-review pass
(`checker-script-adversarial-review`, since this is a `.github/scripts/
*.py` deterministic checker) and one full walk of
`skills/evaluating-deterministic-gate-quality/references/dimensions.md`
against this specific gate (`deterministic-gate-quality`, since it is
registered in `.gitapex/ssot.json`). Both found real, concrete defects
against the *first* draft of this redesign (a version that stripped
quoted spans of any length by rewriting the text): (1) a whole offending
clause wrapped in one long quoted span evaded detection entirely; (2) the
text-rewriting approach let a whitespace-tolerant cue alternative bridge
across a removed span and fabricate a match between unrelated words; (3)
the quoted-span pattern excluded embedded newlines, missing a hard-wrapped
quoted example split across two lines of Markdown source (this
repository's own docs/skills/evals convention). All three are fixed in
the position-filtering redesign above, each with its own regression test
(`test_find_offending_paragraphs_still_flags_fully_quoted_violating_clause`,
`test_find_offending_paragraphs_does_not_bridge_across_an_unrelated_quoted_aside`,
`test_find_offending_paragraphs_recognizes_a_hard_wrapped_quoted_example`).
One risk from the first draft remains, narrower and explicitly disclosed:
a live sentence that quotes only *one* of its two cue phrases (not the
whole clause) can still evade detection -- the reviewing agent confirmed
this specific trade-off is acceptable, matching this repository's
existing non-exhaustive-keyword-heuristic convention (issue #520's own
ACM already disclosed the same class of risk), and the
`tool-fingerprint-disclosure: WAIVED:` marker remains the deterministic
backstop for any case this heuristic still misses.

## Facts established live, this session (correcting the issue's own drift)

The issue's Facts section states that `gitapex_gate_provenance_disclosure.py`
"enumerates a closed set of regex patterns... a \"Generated by ... Claude\"
phrase pattern, `claude.ai/code/session_` URLs, and `claude-[a-z0-9-]+`
model IDs, originating from #36's design and #350's cue-word vocabulary."
That description does not match the file on `main`:

| What the issue says | What the repo actually shows |
|---|---|
| The named file enumerates "Generated by Claude" / session URL / model ID patterns | Those three patterns belong to a *different* file, `skills/outward-artifact-preflight/scripts/gitapex_scan_provenance.py`'s `_PATTERNS` list -- issue #36 repair 1's own proposed gate, already shipped there, and already documented as "Non-exhaustive by design ... Add more patterns as new fingerprint shapes are observed" |
| "#36's design and #350's cue-word vocabulary" combine into one file | They are two separate, already-shipped scripts: #36 -> `gitapex_scan_provenance.py` (a skill pre-submission check, not a CI gate); #350 repair 1 -> `gitapex_gate_provenance_disclosure.py` (the actual CI gate, id `provenance-disclosure`) |
| The gate's actual matching logic | `_LIMITATION_CUE_RE` (a reason/limitation cue) AND `_TOOL_CUE_RE` (a tool-fingerprint cue) must co-occur in one paragraph -- an entirely different concern (undisclosed tool-fingerprint-as-justification prose) than "Generated by Claude" style production markers |
| "Preserve ... the original incidents this gate was built for (#36's cases)" | This gate was never built for #36's cases (those are `gitapex_scan_provenance.py`'s scope) -- its own original positive case is #350's, verified via `tests/test_gitapex_gate_provenance_disclosure.py`'s pre-existing `_UNDISCLOSED_NOTE` fixture |

The file path and gate id the issue names are both correct, and the
underlying request -- the gate's cue-word vocabulary is a closed
enumeration by CLAUDE.md section 4's own standard, and issue #549
documents a real, already-partially-repaired self-trigger against it --
holds up under inspection (issue #549 repairs 1 and 8, `.github/scripts/`
retrospectives #36/#350/#549 all read directly). Only the issue's
_concrete pattern examples_ and its #36 cross-reference are stale,
carried over from conflating the two related-but-distinct scripts. This
plan targets the real file and its real mechanism; the issue's ACM rows
below are corrected accordingly rather than implemented as literally
written.

Residual risk (disclosed, not fixed): the literal historical text that
self-triggered the gate in PR #539 (issue #549 repair 1, the PR body's
own Facts section) was never committed to git history -- it was edited
before the commit landed, and #549's own retrospective deliberately
avoided reproducing it verbatim to avoid re-triggering the gate on
itself. The regression fixture added here (`_RECONSTRUCTED_PR539_FACTS_SECTION`
in the test file) reconstructs the documented *shape* (a PR Facts section
quoting the gate's own cue-word vocabulary as an example) from repair 1's
description, not the literal original wording.
